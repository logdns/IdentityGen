## 架构与修改入口

项目保持原生 HTML/CSS/JavaScript + 零第三方应用依赖的 Node.js，配置使用 JSON，不需要数据库或构建链。不要为了普通功能改动引入框架或打包器。

| 文件 | 修改场景 |
| --- | --- |
| `index.html`、`style.css` | 身份卡、地图、BIN 弹窗结构、响应式与主题 |
| `app.js`、`data.js` | 四国生成、接口和本地回退、语言、地图、前台配置及正文广告 |
| `bin-ui.js` | BIN 弹窗交互、结果归一展示、国旗与四语言 |
| `bin-lookup.js` | 固定上游、归一化、缓存、超时、限流和回退 |
| `ad-code.js` | 前台、后台和 Node 共用的广告编解码、类型与执行模式 |
| `admin.html` | 认证、九模块导航、设置保存、接口测试和广告诊断 |
| `server.js` | 配置、公开/管理员投影、静态服务、BIN 代理、Head 注入和在线更新 |
| `config.example.json` | 新字段默认值；真实配置不写进模板 |
| `VERSION`、页面资源版本参数 | 版本显示与缓存失效；发布时同步 |
| `tests/` | 单元、临时服务集成、可选完整广告浏览器回归 |

### 配置与部署边界

运行时 `config.json` 包含密码和 Key，不能进 Git、归档或截图；升级不能用模板覆盖。测试使用临时副本和假配置，避免真实服务启动时创建配置或轮换旧默认密码。

生产 Node 默认监听 `127.0.0.1`，前方使用 HTTPS 反向代理，80 端口只做跳转。`X-Real-IP` 只在直接连接来自回环时受信，代理须覆盖访客输入；不要推广成任意代理链都可信。配置、常见备份名称及隐藏路径被静态拦截，但备份仍放在网站根目录外。

部署文件需包括 `bin-lookup.js`、`bin-ui.js`、`ad-code.js`，更新后重启 Node 并刷新缓存。`/api.php` 是兼容路由，并非仓库附带的 PHP 实现；旧 PHP 后端不能替代新 BIN/Head 功能。

当前在线更新允许先 stash 未提交代码，再快进 pull；成功后本地改动保留在 stash，失败尝试恢复。本地提交或分叉需人工处理；不能笼统描述为“所有脏工作区都拒绝更新”。

## 接口保留与回退

### 身份和地址

| 国家 | 内部代码 | RandomUser nat | FakerAPI locale |
| --- | --- | --- | --- |
| 美国 | us | us | en_US |
| 英国 | uk | gb | en_GB |
| 德国 | de | de | de_DE |
| 土耳其 | tr | tr | tr_TR |

- 姓名/个人信息：FakerAPI → RandomUser → 本地；后台保留两个独立测试入口。
- 随机地区地址：RandomUser v1.4；明确选择州/地区：Nominatim → 本地。
- 地图：RandomUser 地址使用完整地址查询；指定地区的 Nominatim 坐标检查国家代码及合理范围后才直用。范围检查不代表街道位置精确。
- 首次访问即写入地图 URL，iframe 使用 eager；不能用第二次生成成功代替首访测试。
- 使用 generation 序号避免旧请求覆盖新国家结果；上游不可用时保持页面恢复和本地生成。
- 前台为十个字段；不重新加入已删除的 Email/Website。生成身份和证件号属于示例数据，不能视为真人或真实有效证件。

文档： [RandomUser](https://randomuser.me/documentation#nationalities)、[FakerAPI](https://fakerapi.it/)、[Nominatim](https://nominatim.org/release-docs/latest/api/Overview/)。开发时重新核对当前条款，不将以前遇到的 FakerAPI 502 描述成今天仍故障。

### BIN/IIN

前台只提交恰好 6 位 BIN 或 8 位 IIN，JSON POST 到 `/api?action=binlookup`。完整卡号不接受、不截断，不能用于余额、持有人或卡片有效性验证。

HandyAPI 使用固定 HTTPS 主机和 `x-api-key`，优先 Secret；Binlist 使用 `Accept-Version: 3`，回退只查前 6 位，并展示来源、实际查询前缀和精度。未知值保留未知，布尔 false 不误判成缺失，不为成功结果拼接另一个卡段。

Secret 不返回前台或管理员配置响应；留空表示保留，清除为独立操作。缓存绑定凭据/来源，查询合并、并发、响应长度和超时均受限。当前阈值与详情见 README/源码；进程重启会重置内存配额，多实例不等于共享配额。独立测试同样可能消耗配额或命中缓存。

处理上游时先安装 error/aborted 监听再分支状态，错误正文及时终止；入站异步错误在请求层捕获。DOM 使用文本方式显示结果。配置保存、接口测试和前台查询需分别覆盖。

文档：[HandyAPI GitHub](https://github.com/selay/handyapi-card-bin-list)、[HandyAPI](https://www.handyapi.com/bin-list)、[Binlist](https://binlist.net/)。

## 广告对接经验

### v1.2.22：左右对联广告

新增 `left`、`right` 两个独立广告位，统一使用 `AdCode.SLOTS`，避免前台、后台、服务端的广告位清单漂移。保存时合并广告槽位，旧客户端只提交四个广告位时不清空新的左右广告；旧配置缺少字段默认关闭。每槽仍限制编码后 30,000 字符，六槽最大数据在现有 256 KiB 请求上限内。

对联广告在宽度 ≥ 1440px 的屏幕加载并固定在主内容两侧，布局宽度最多 160px，较小宽屏适合 120px 素材；160px 素材建议 ≥ 1504px。平板和手机不新加载隐藏广告；宽窄窗口切换保留已加载实例，避免重复请求。访客分别关闭后本页不再显示，刷新恢复；后台独立禁用控制所有访客。关闭按钮与广告标识适配四语言和键盘操作。

回归覆盖两侧开关/代码/执行方式的保存与重载、旧配置与部分更新、窄屏不请求、首次扩宽加载、缩窄/扩宽复用、关闭/刷新、主内容不重叠、BIN 弹窗及原有广告链路。低高度窗口的滚动广告保留可操作的关闭按钮。测试使用临时配置和模拟脚本，不验证真实平台填充；发布制品按不可变 tag 构建并校验。

### 故障来源

旧实现会在短暂空白后移除慢加载广告、丢失 `document.write` 多参数、共享广告位全局变量，以及在切换国家/语言后重复执行。纯 JS、脚本 URL 与 Head 处理不一致，长代码还可能被静默截断。

### 当前约定

1. `ad-code.js` 提供同一套 UTF-8/Base64 编码和规范化；支持旧 raw HTML。编码不是加密或安全过滤。
2. 保存后核对原始代码、enabled、format、mode；非法/过长代码在写入前拒绝，不继续截断。旧版本已丢失的内容需重贴。
3. Head 由 Node 在首页响应中注入；Nginx/PHP 直接返回静态首页会绕过它。仅有加载器不意味着已有横幅容器或库存。
4. 普通 JS 默认独立广告文档，保留原生解析、顺序加载及变量隔离；AdSense/GPT 默认页面内，也允许手动选择。
5. 独立同源 iframe 只隔离布局/变量，不是安全沙箱；管理员只应配置可信平台代码。页脚品牌 HTML 是受限文案，不是广告 JS 执行入口。
6. 延迟填充保留占位，观察尺寸/内容变化；相同配置不因国家/语言变化重执行。替换/关闭时清理 observer。
7. 后台「检查已保存配置」比对公开配置及 Head 注入，不执行广告；「查看前台诊断」打开 `?ad_debug=1`，提示加载/空白/内容/错误。

排障顺序：是否启用 → 保存与返回是否一致 → 新模块与 Node 是否已升级 → 公开配置/Head → Console/Network → 容器/平台填充。域名审核、库存、地区、HTTPS、CSP、隐私策略和拦截器仍可能导致空白，不能用插入标签或 HTTP 200 宣称广告投放成功。

## 可复用发布流程

- 先确认当前工作区、远端/分支、发布授权和 tag/Release 未占用；新增功能、文档整理不自动授权发布。
- 更新 `VERSION`、资源缓存参数与迁移说明；检查每份部署清单是否包含新增模块；保留生产配置。
- 运行相关回归与审查，显式暂存包括新测试/模块的文件；遇到非本次改动或远端漂移先停下确认。
- 从已提交、不可变的版本 tag 构建 tar.gz/zip，而不是压缩工作目录；比对 Git 文件树及字节，排除真实配置/Key/备份和特殊文件。
- 生成 SHA256SUMS，若声称可复现则重建比较；原子推送 main/tag，再创建 Release 并上传所选制品。
- 回下载到新目录，与本地可信哈希清单及包字节比较；确认远端分支/tag/提交、Release 状态、工作区和运行时配置完整性。
- 部分推送或上传失败先检查远端实际状态再续做，不覆盖已存在 tag，不删除已发布版本来重试。
